# نظام متابعة إنجاز الطلاب

نظام محلي (React + Vite + Supabase) لمتابعة إنجاز الطلاب في المتون، بتصميم زجاجي داكن (Glassmorphism).

## التشغيل — الوضع التجريبي (بلا Supabase)

هذا هو الوضع الافتراضي. لا يحتاج قاعدة بيانات ولا إنترنت:

```bash
npm install
npm run dev
```

يعمل النظام ببيانات وهمية محفوظة في `localStorage` داخل متصفحك: ثلاثة حسابات، وخمسة عشر طالباً موزّعين على حلقتين. كل شيء يعمل فعلياً — الإضافة، الملاحظات، البحث، الترتيب، الواتساب، وCSV — وتبقى تعديلاتك بعد إعادة تحميل الصفحة. زر «إعادة التعيين» في الشريط العلوي يرجّع البيانات لحالتها الأصلية.

| النوع | الاسم | رمز الدخول | الحلقة |
|------|------|-----------|--------|
| أدمن | المدير العام | `ADMIN-1443` | — |
| محفّظ | عبدالرحمن الشمري | `T-101` | الأولى (عشرة طلاب) |
| محفّظ | سعد الحربي | `T-102` | الثانية (4 طلاب) |

## التشغيل — الوضع الحقيقي (Supabase)

```bash
supabase start                    # انسخ الـ URL و anon key
cp .env.example .env              # واملأ VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY
# الصق supabase/schema.sql في Supabase Studio > SQL Editor وشغّله
npm run dev
```

بمجرد وجود المتغيّرين في `.env` يتحول النظام تلقائياً إلى Supabase ويختفي شريط الوضع التجريبي. لإجبار الوضع التجريبي رغم وجودهما، ضع `VITE_DEMO=true` في `.env`.

### كيف يعمل التبديل

[supabaseClient.js](src/lib/supabaseClient.js) يصدّر إمّا العميل الحقيقي أو [mockClient.js](src/lib/mockClient.js) الذي يحاكي نفس واجهة supabase-js (`from().select().eq().order()`، `insert().select().single()`، `update().eq()`، و`rpc('login_user')`) مع تأخير 180ms لمحاكاة الشبكة. **الصفحات والمكوّنات لا تعرف أي وضع يعمل** — ولا سطر واحد فيها يتغيّر.

## سلوك واجهة المحفّظ

- **نافذة إضافة طالب**: أربعة حقول — اسم الطالب، المستوى، ملاحظة، رقم ولي الأمر. رقم الطالب يُولَّد تلقائياً (أكبر رقم في النظام + 1) ولا يُعرض في الجدول لكنه يبقى قابلاً للبحث، والمتن يُشتق من المستوى عبر [levels.js](src/utils/levels.js)، ونسبة الإنجاز تبدأ من صفر.
- **جدول الطلاب**: أعمدة العرض هي اسم الطالب، المستوى، (المحفّظ للأدمن)، نسبة الإنجاز، ملاحظة، إجراءات. عمود «رقم الطالب» أُزيل من العرض.
- **نسبة الإنجاز**: تُعدّل مباشرة من خلية الجدول. تُحفظ عند مغادرة الحقل أو بالضغط على Enter، وتُثبَّت القيمة بين صفر و100.
- **الإجراء الوحيد — «إنشاء رسالة ولي الأمر بصيغة رسمية»**: يبني الرسالة الرسمية من بيانات الصف الحالية (بما فيها النسبة بعد تعديلها)، ويُدرج الملاحظة في السطر الأخير فقط إن كانت مدوّنة، ويوجّهها إلى `wa.me/<رقم ولي الأمر>`. الصيغة محدّدة حرفياً في `buildGuardianMessage` داخل [whatsapp.js](src/utils/whatsapp.js) ولا يجوز إضافة أي نص إليها. «مراسلة الجميع» تستخدم الصيغة نفسها.
- **أرقام الهواتف**: تُطبَّع إلى الصيغة الدولية بلا `+` عبر [phone.js](src/utils/phone.js). مفتاح الدولة الافتراضي `218` (ليبيا) — غيّر `DEFAULT_COUNTRY_CODE` إن لزم. `0925550123` تُحفظ `218925550123`.

## نموذج إضافة محفّظ (الأدمن الرئيسي)

ثلاثة حقول حصراً: اسم المحفّظ، رمز الدخول، رمز الحلقة. عمود قاعدة البيانات ما زال اسمه `halaqa_number` لتجنّب ترحيل بيانات؛ الواجهة كلها تسمّيه «رمز الحلقة».

## قواعد ثابتة في الكود

- **الرقم عشرة**: كل رقم يظهر للمستخدم يمر عبر `ar()` في [src/utils/numbers.js](src/utils/numbers.js). القيمة `10` تُعرض دائماً «عشرة» — في الإحصائيات، الجدول، النِّسَب، التنبيهات، ورسائل الواتساب.
- **الحفظ المباشر**: نماذج إضافة الطالب والمحفّظ تكتب في قاعدة البيانات فوراً بزر حفظ واحد. لا مسودات ولا مراحل مراجعة.
- **البحث**: يفلتر باسم الطالب ورقم الطالب فقط.

## ملاحظة أمنية

المصادقة مخصّصة (اسم + رمز دخول) ولا تستخدم Supabase Auth، لذلك لا يوجد JWT تعتمد عليه سياسات RLS للتمييز بين المستخدمين:

- عمود `passcode` **غير قابل للقراءة** من العميل (منعت صلاحيته على مستوى العمود)، والتحقق يتم عبر دالة `login_user` بصلاحية `SECURITY DEFINER`.
- بقية العمليات مسموحة لدور `anon`، والفصل بين المحفّظين يتم في طبقة التطبيق (`teacher_id`).

هذا مقبول لنظام يعمل على شبكة محلية موثوقة، **وغير مقبول للنشر العلني** لأن أرقام هواتف أولياء الأمور تصبح قابلة للقراءة لأي شخص يعرف الرابط. اقرأ قسم التحذير في [DEPLOY.md](DEPLOY.md) قبل النشر على GitHub Pages بمفاتيح Supabase حقيقية.
